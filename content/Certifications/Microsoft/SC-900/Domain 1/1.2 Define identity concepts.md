## Describe Defense in depth
- this is. basically a layered approach to security 
- **Physical** security such as limiting access to a datacenter to only authorized personnel.
- **Identity and access** security controls, such as multi-factor authentication or condition-based access, to control access to infrastructure and change control.
- **Perimeter** security of your corporate network includes distributed denial of service (DDoS) protection to filter large-scale attacks before they can cause a denial of service for users.
- **Network** security, such as network segmentation and network access controls, to limit communication between resources.
- **Compute** layer security such as securing access to virtual machines either on-premises or in the cloud by closing certain ports.
- **Application** layer security to ensure applications are secure and free of security vulnerabilities.
- **Data** layer security including controls to manage access to business and customer data and encryption to protect data.

##  Directory services 
Active directory is a set of directory services developed by Microsoft as mart of windows 2000 for on premises domain-based networks.

Gives organizations the ability to manage multiple on-premises infrastructure components and systems using a single identity per user.

Does not natively support mobile devices, SaaS or LOB apps that require modern authentication


#### Forest
- This is the highest level logical container in the directory servce:
	- A forest is a security coundry that groups one or more domain trees together under a single shared schema and a global catalog 
	- even if a forest contains multiple domains they all trust each other by default because they re part of the same forest 
- Imagine a forest as a company 
- inside the company you can have multiple departments(domains) - like HR, sales, IT, each with its own structure, rules and user accounts but all following the same company wide policies and rules(schema)
	- the company as. whole is the forest
- **Forest** = The entire Active Directory environment.
    
- **Domains** = Subsections within the forest, each with its own users, groups, and policies.
    
- **Trees** = A collection of domains that share a contiguous namespace.
    
- All domains in a forest automatically trust each other (transitive trust).
    
- Forests can have multiple domain trees that don't necessarily share a name, but they share the same schema and global catalog.
|Forest Name|Domain Names|
|contoso.com (Forest)|contoso.com (Domain), sales.contoso.com, hr.contoso.com|
|fabrikam.com (another Forest)|fabrikam.com, support.fabrikam.com|

- Each forest is isolated from others unless you explicitly set up a **trust relationship** between them.

#### Kerberos
**Kerberos** is a secure network authentication protocol designed to allow computers and users to prove their identity over a non-secure network (like your LAN) — without sending passwords in plain text.

- **User logs in** → Enters username and password on their workstation.
    
- The workstation uses the password to request a **Ticket Granting Ticket (TGT)** from the **Key Distribution Center (KDC)**, which lives on the **Domain Controller**.
    
- If the password is correct, the **KDC** issues the **TGT**.
    
- When the user tries to access a service (like a file server, print server, or web service), the TGT is presented to the KDC again, asking for a **Service Ticket** for that specific service.
    
- The KDC issues the **Service Ticket**.
    
- The user presents the Service Ticket to the target service, which verifies it — and access is granted without the password ever being sent directly to the service.

#### Replication
Replication is how Active Directory ensures that all Domain Controllers stay in sync — so whether you log in at your office or at a remote site, your credentials and permissions will work as expected

|Concept|Purpose|
|---|---|
|**Replication**|Copies changes from one DC to others.|
|**Synchronization**|The goal — all DCs have the same view of the directory data.|
|**KCC**|Builds and optimizes the replication paths.|
|**Intrasite**|Fast, local updates.|
|**Intersite**|Scheduled, efficient long-distance updates.|

## Concept of federation
A Federation is a collection of domains that have established trust 
- The level of trust may vary but typically includes authentication and almost always includes authorization
- Often includes a number of organizations that have established trust for shared access to a set of resources  
Eg:
You can federate your on-premisis environment with Entra ID and use this federation for authentication and authorization.
This method ensures that all user authentication occurs on-premises.
Allows administrators to implement more rigorous levels of access control such as certificate authentication and, key fob card token 


Example:

**Federation** in Microsoft Entra ID refers to **trust relationships between Entra ID and external identity providers**. This allows users to **sign in using their existing credentials** from another identity system, such as:

- On-premises Active Directory (via ADFS)
    
- Google Workspace
    
- Facebook, SAML, or OpenID Connect providers
    

Basically, federation lets users **authenticate somewhere else**, and Entra ID **trusts that authentication**.
