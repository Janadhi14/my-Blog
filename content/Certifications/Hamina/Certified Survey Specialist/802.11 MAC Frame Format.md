# 802.11 MAC Frame Format

## Frame Control

### Protocol Version:
Always 00

### Type:
* 00 Management : Manage the BSS
* 01 Control : Control the flow of data
* 10 Data : Carry data (well most of the time!)
* 11 Extension : DMG (Directional Multi-Gigabit) Frames (802.11ad)

### Sub Type:
Defines the subtype of Management, Control or data frames. Some examples of subtype values are in the table opposite:
* 00 Management 0000 Association Request
* 00 Management 0001 Association Response
* 00 Management 0010 Reassociation Request
* 00 Management 0011 Reassociation Response
* 00 Management 0100 Probe Request
* 00 Management 0101 Probe Response
* 00 Management 1000 Beacon
* 00 Management 1001 Announcement Traffic Indication Message
* 00 Management 1010 Disassociation
* 00 Management 1011 Authentication
* 00 Management 1100 Deauthentication
* 01 Control 1010 Power Save (PS)-Poll
* 01 Control 1011 RTS
* 01 Control 1100 CTS
* 01 Control 1101 Acknowledgement
* 10 Data 0000 Data
* 10 Data 0100 Null Function

### To DS / From DS:
* To DS Packet travelling to the Distribution System
* From DS Packet travelling from the Distribution System
* Management and Control frames set both the To DS and From DS bits to 0

| To DS | From DS | Network         |
|-------|---------|-----------------|
| 0     | 0       | Ad-Hoc          |
| 1     | 0       | Infrastructure: To access point |
| 0     | 1       | Infrastructure: From access point |
| 1     | 1       | Bridge Link     |

### More Frag:
Set to 1 if another fragment of the same MPDU (MAC Protocol Data Unit) is to follow

### Retry:
Set to 1 when the frame is a retransmission

### Power Management:
* To conserve battery life, mobile devices can use power management to periodically power down their wireless cards (“Go to sleep”)
* Devices tell the Access Point they are going to sleep by setting the power management bit to 1
* The Access Point will then buffer frames for that station until the STA wakes up
* STAs must wake up for beacons (but not every one)
* A special field in the beacon call the TIM (Traffic Indication Map) tells clients if the access points has any frames buffered for them

### More Data:
Tells a station in power save mode that there are more buffered data frames for them, so stay awake

### Protected:
* Indicates that the frame body has been encrypted
* Some analysers still decode this field by its old name “WEP”, but it is also set when using TKIP and AES.

### +HTC/Order:
* **802.11 – 1997: Order**
  * Set by a higher layer which says frame must be processed in a strict order
  * If this bit is set, station cannot use power management
* **802.11e: Order**
  * All QoS frames must set the Order bit to 0
* **802.11n: HTC+**
  * All 802.11n MCS frame are QoS frames
  * HTC+ bit is set to 1 to indicate the frame has a HT control field

## Duration / ID

### ID:
Used in a PS-Poll frame to indicates the Association ID of the STA Values 0 - 2007

### Duration:
Time in microseconds needed to complete the frame exchange Values 0 – 32,767 Used to update stations NAV (Network Allocation Vector)

## Address Fields
Each of the four 802.11 address fields may have one of five different interpretations:
* DA Destination Address (Final Destination)
* SA Source Address (Start Point)
* RA Receiver Address (Next Wireless Destination)
* TA Transmitter Address (Station that has transmitted the frame onto the WM)
* BSSID Basic Service Set Identifier

## Interpreting 802.11 address fields
This table applies only to data frames.

| To DS | From DS | Address 1 (RA) | Address 2 (TA) | Address 3 | Address 4 |
|-------|---------|----------------|----------------|-----------|-----------|
| 0     | 1       | DA             | BSSID          | SA        | N/A       |
| 1     | 0       | BSSID          | SA             | DA        | N/A       |
| 0     | 0       | DA             | SA             | BSSID     | N/A       |
| 1     | 1       | RA             | TA             | DA        | SA        |

Protocol analysers will interpret these address fields for you

## Sequence Control

### Fragment Number:
Sequences every fragment of MPDU starts at 0 and increment by 1

### Sequence Number:
Identifies the MPDU ID begins at 0 and goes up to 4095 Will be the same for every fragment Gaps in sequence numbers = missing packets



## Detailed 802.11 MAC Frame Format
The IEEE 802.11 standard defines the Media Access Control (MAC) layer frame format, which is crucial for how Wi-Fi devices communicate. Understanding this format is essential for network analysis, troubleshooting, and security. The MAC frame consists of several fields, each serving a specific purpose.

### Frame Control Field
The Frame Control field is a 16-bit field that contains several subfields, providing critical information about the type and function of the 802.11 frame.

*   **Protocol Version (2 bits):** This field indicates the version of the 802.11 protocol being used. Currently, it is always set to `00` for the existing 802.11 standards. This ensures backward compatibility and allows for future protocol revisions.

*   **Type (2 bits):** This subfield categorizes the 802.11 frame into one of four main types:
    *   `00` **Management Frames:** These frames are used for managing the wireless connection, such as establishing and maintaining communication between stations (STAs) and access points (APs). They handle functions like authentication, association, and beaconing.
    *   `01` **Control Frames:** These frames assist in the delivery of data frames by controlling access to the wireless medium. They are used for functions like acknowledging successful transmissions (ACK), requesting to send (RTS), and clearing to send (CTS).
    *   `10` **Data Frames:** These frames are responsible for carrying the actual user data (payload) between stations. While primarily for data, some data frames can also carry control information.
    *   `11` **Extension Frames:** This type was introduced for future extensions, such as Directional Multi-Gigabit (DMG) frames used in 802.11ad (WiGig) for very high-speed, short-range communication.

*   **Subtype (4 bits):** This subfield further defines the specific function of the frame within its main Type category. For example:
    *   **Management Frame Subtypes:**
        *   `0000` **Association Request:** A station requests to associate with an access point.
        *   `0001` **Association Response:** An access point responds to an association request.
        *   `0010` **Reassociation Request:** A station requests to reassociate with an access point (e.g., when roaming).
        *   `0011` **Reassociation Response:** An access point responds to a reassociation request.
        *   `0100` **Probe Request:** A station sends a request to discover available access points.
        *   `0101` **Probe Response:** An access point responds to a probe request, advertising its capabilities.
        *   `1000` **Beacon:** An access point periodically broadcasts this frame to announce its presence and network parameters.
        *   `1001` **Announcement Traffic Indication Message (ATIM):** Used in IBSS (Ad-Hoc) networks for power management.
        *   `1010` **Disassociation:** A station or AP terminates an association.
        *   `1011` **Authentication:** A station attempts to authenticate with an access point.
        *   `1100` **Deauthentication:** A station or AP terminates an authentication.
    *   **Control Frame Subtypes:**
        *   `1010` **Power Save (PS)-Poll:** A station in power-save mode requests buffered frames from the AP.
        *   `1011` **Request To Send (RTS):** Used to reserve the medium for a data transmission.
        *   `1100` **Clear To Send (CTS):** Sent in response to an RTS, granting permission to transmit.
        *   `1101` **Acknowledgement (ACK):** Confirms successful reception of a frame.
    *   **Data Frame Subtypes:**
        *   `0000` **Data:** Carries the primary user data.
        *   `0100` **Null Function:** A data frame with no payload, often used for power management or to signal a change in a station's state.

*   **To DS / From DS (1 bit each):** These two bits indicate the direction of the data frame relative to the Distribution System (DS), which is typically the wired network connected to the access point. For management and control frames, both bits are set to `0`.

    | To DS | From DS | Network Type / Direction |
    |-------|---------|--------------------------|
    | 0     | 0       | **Ad-Hoc (IBSS):** Frames exchanged directly between stations in an independent basic service set. |
    | 1     | 0       | **Infrastructure: To Access Point:** Frames originating from a wireless station and destined for the wired network via an access point. |
    | 0     | 1       | **Infrastructure: From Access Point:** Frames originating from the wired network and destined for a wireless station via an access point. |
    | 1     | 1       | **Wireless Distribution System (WDS) / Bridge Link:** Frames exchanged between access points in a WDS, where both APs are acting as bridges. |

*   **More Frag (1 bit):** This bit is set to `1` if the current MAC Protocol Data Unit (MPDU) is fragmented and there are more fragments of the same MPDU to follow. If it's the last fragment or an unfragmented frame, it's set to `0`.

*   **Retry (1 bit):** This bit is set to `1` when the frame being transmitted is a retransmission of a previously sent frame. This helps the receiver identify duplicate frames and discard them if the original was already received.

*   **Power Management (1 bit):** This bit is used by stations to signal their power-saving state to the access point. If a station sets this bit to `1`, it indicates that it is entering a power-save mode (going to sleep). The access point will then buffer any frames destined for that station until the station wakes up and requests them. Stations must periodically wake up to listen for beacons and check for buffered frames.

*   **More Data (1 bit):** This bit is set by the access point to inform a station in power-save mode that there are more buffered data frames waiting for it. This tells the station to stay awake and continue receiving data rather than going back to sleep.

*   **Protected (1 bit):** This bit indicates whether the frame body has been encrypted. If set to `1`, it means the frame payload is protected by an encryption mechanism (e.g., WEP, TKIP, AES). While some older analyzers might decode this field as "WEP," it signifies encryption regardless of the specific algorithm used.

*   **+HTC/Order (1 bit):** The interpretation of this bit has evolved across 802.11 standards:
    *   **802.11-1997 (Original Standard): Order:** In the original standard, if this bit was set, it indicated that the frame must be processed in a strict order by a higher layer. If this bit was set, the station could not use power management.
    *   **802.11e (Quality of Service - QoS): Order:** For QoS frames introduced in 802.11e, the Order bit must be set to `0`.
    *   **802.11n (High Throughput - HT): HTC+:** In 802.11n and later high-throughput standards, this bit is repurposed as the "HTC+" bit. If set to `1`, it indicates that the frame includes an HT Control field, which carries information related to High Throughput operations (e.g., beamforming, A-MPDU).

### Duration / ID Field
This 16-bit field serves a dual purpose depending on the frame type:

*   **ID (Identification):** When the frame is a Power Save (PS)-Poll frame, this field contains the Association ID (AID) of the station that is sending the PS-Poll. The AID is a unique identifier assigned to a station when it associates with an access point, ranging from `0` to `2007`.

*   **Duration:** For most other frame types, this field specifies the duration (in microseconds) for which the network medium will be reserved for the current transmission and its immediate acknowledgment. The value ranges from `0` to `32,767` microseconds. This duration value is used to update the Network Allocation Vector (NAV) of other stations, informing them to defer their transmissions to avoid collisions. This mechanism is part of the Distributed Coordination Function (DCF) for medium access control.

### Address Fields
An 802.11 MAC frame can have up to four address fields, each 6 bytes long, used to identify the source and destination of the frame. Their interpretation varies depending on the To DS and From DS bits in the Frame Control field, particularly for data frames. The five possible interpretations for each address field are:

*   **DA (Destination Address):** The MAC address of the final destination of the frame.
*   **SA (Source Address):** The MAC address of the original source of the frame.
*   **RA (Receiver Address):** The MAC address of the next wireless device that is expected to receive the frame (the immediate recipient).
*   **TA (Transmitter Address):** The MAC address of the wireless device that has just transmitted the frame onto the wireless medium (the immediate sender).
*   **BSSID (Basic Service Set Identifier):** The MAC address of the access point for an infrastructure BSS, or a randomly generated MAC address for an independent basic service set (IBSS/Ad-Hoc network).

**Interpreting 802.11 Address Fields (for Data Frames):**

| To DS | From DS | Address 1 (RA)          | Address 2 (TA)          | Address 3               | Address 4               |
|-------|---------|-------------------------|-------------------------|-------------------------|-------------------------|
| 0     | 0       | DA (Destination Address) | SA (Source Address)     | BSSID                   | N/A                     |
| 1     | 0       | BSSID                   | SA (Source Address)     | DA (Destination Address) | N/A                     |
| 0     | 1       | DA (Destination Address) | BSSID                   | SA (Source Address)     | N/A                     |
| 1     | 1       | RA (Receiver Address)   | TA (Transmitter Address) | DA (Destination Address) | SA (Source Address)     |

*Note: Protocol analyzers (like Wireshark) are designed to automatically interpret these address fields for you, making it easier to understand the flow of traffic.*

### Sequence Control Field
This 16-bit field is crucial for managing frame order and retransmissions, especially in the presence of fragmentation.

*   **Fragment Number (4 bits):** This subfield indicates the order of fragments for a fragmented MPDU. It starts at `0` for the first fragment and increments by `1` for each subsequent fragment of the same MPDU.

*   **Sequence Number (12 bits):** This subfield identifies the unique ID of the MPDU. It starts at `0` and goes up to `4095`. All fragments belonging to the same MPDU will have the same Sequence Number. Gaps in sequence numbers indicate missing packets, which can be a sign of packet loss or interference. This field is vital for reliable data delivery and reassembly of fragmented frames at the receiver.
